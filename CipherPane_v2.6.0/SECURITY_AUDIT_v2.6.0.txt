CIPHERPANE BROWSER SECURITY v2.6.0 — RENAME, CLEANUP AND HARDENING AUDIT
=======================================================================

Scope
-----
Source review of the v2.5.1 package (all JavaScript, HTML, manifest and static rules), followed by a rename,
dead-code removal and hardening. Method: read every source file; scan for unused symbols, exports, CSS
classes and HTML ids; write a test for each change; revert each change in a scratch copy to confirm the
test fails without it (mutation check).

HARDENING
---------
H1  Registry suffixes could be blocked by a downloaded feed.
    DNR domain rules match a domain and all its subdomains, so one bad line ("co.uk", "com.au") in an upstream
    feed would have blocked every site under that suffix. The v2.5.1 never-block list covered only a fixed set
    of large apex domains.
    Fix: lists.js isProtected() now also rejects two-label "SLD.ccTLD" entries (co, com, org, net, gov, edu,
    ac, or, ne, go, gob, mil, nom, ltd, plc, sch). Applies to freshly downloaded lists, persisted lists and
    mergedBulk(). Real sites under a suffix (shop.co.uk) stay blockable. Your own custom blocks and manual
    imports are not filtered.
    Residual risk: this is a shape check, not the Public Suffix List. Other shared-hosting parents can still be
    listed by a feed; the feeds remain a trusted input. Tests: unit + updater (poisoned feed). Mutation: caught.

H2  Extension-page CSP was allow-listed, not default-deny.
    Fix: added default-src 'none', frame-src 'none', worker-src 'self' to the existing script/style/img/connect
    rules. tools/build.js and the test suite check for them and for the absence of unsafe-inline/eval.
    Not live-tested in a browser: if a page loses a resource, the browser console will name the directive.

H3  Framed block page.
    blocked.html is web-accessible, so any web page can embed it. Its "review in Settings" button now stays
    hidden when the page is not the top-level document. (The button only opens the Settings page with a
    pre-filled box and never adds anything by itself, so this removes a clickjacking surface rather than a
    demonstrated exploit.) Tested against a stub DOM (tests/pages.js), not a real browser. Mutation: caught.

H4  Warning-page target validation.
    nohttps.js and the worker (nohttpsContext) now refuse a target URL longer than 2,048 characters or with
    embedded credentials (user:pw@host). The worker stores an HTTPS-fallback hint only for requests whose URL
    is within that bound. Tests: worker and page script both refuse both cases. Mutation: caught.

H5  Message field shape.
    ALLOW_HTTP: host must be a string of at most 253 characters (previously an object with a toString() method
    was coerced and could match the warning page's host). Test + mutation: caught.
    ALLOW_DOWNLOAD: id must be a string of at most 64 characters. Defense in depth only: a non-string id never
    matched a stored entry before either, so this is not independently observable (mutation check survived,
    as expected). Kept because it fails earlier and costs nothing.

CLEANUP
-------
C1  Removed unused code:
    - reputation.js: visualLabel() (no callers anywhere) and the cleanHost export (internal use only).
    - lists.js: SOURCES[].url (never read; only SOURCES[].urls is used).
    - background.js: unused "src" parameter of fetchOne(); comment naming a symbol that is not exported.
    - popup.js: parseFilterLines wrapper, duplicated MAX_* constants (now CipherLists.LIMITS), duplicated
      fmtAge (now CipherLists.fmtAge, shared with options.js).
C2  Removed from the package: stale SECURITY_AUDIT_v2.5.0.txt, the pre-rename manual, generated dist/ inside
    the source zip, duplicated changelog blocks in README.txt.
C3  Checked and kept (not dead): CSS classes log-ALLOWED/log-BLOCKED/log-ERROR (class names are built at
    runtime), tab ids shieldTab/bulkTab (selected through data-tab), editDistance/parseHost/domainsFromLine
    exports (used by the tests).

RENAME
------
Product name, UI text, manifest, Firefox ID (cipherpane-security@local.extension), global names
(CipherLists, CipherReputation), alarm names, export file name and format (cipherpane-settings; the old
aegisgate-settings still imports). Storage keys are unchanged. Because the Firefox ID changed, Firefox treats
this as a new add-on: export from the old one and import here.

RESULT
------
node tests/run.js: 32 lists/rules/packaging test groups, 3 page-script tests and 22 worker runtime tests pass
(previously 27, 0 and 19). The tests use a mocked browser API and a stub DOM.

NOT DONE / NOT CLAIMED
----------------------
No live Chrome, Brave, Edge or Firefox test, no independent penetration test, no certification. The extension
runs inside the browser it protects and cannot filter other applications; it is not "hacker-proof".
Feed mirrors were not downloaded during this audit (no network); use Update now in Settings to confirm them.
